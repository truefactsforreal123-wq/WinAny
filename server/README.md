# Signaling service

Run `npm install`, `npm test`, `npm run typecheck`, and `npx wrangler dev` from this directory. No credentials are shipped. Configure `TURN_KEY_ID` and `TURN_KEY_API_TOKEN` as Worker secrets, and set `TURN_DAILY_BUDGET` to a positive integer to enable TURN issuance. The default is zero (disabled). Each UTC day has a persistent hard issuance-attempt budget; each participant in an accepted session allows at most two attempts, including failed upstream calls. TURN upstream requests time out after five seconds. Cloudflare issues credentials with a 3600-second TTL via its [Realtime TURN API](https://developers.cloudflare.com/realtime/turn/generate-credentials/). The Worker cannot measure actual TURN bytes or guarantee free-tier billing: limit budgets and monitor Cloudflare independently.

The [protocol](PROTOCOL.md) uses a single Durable Object with hibernating WebSockets and persistent device keys, session state and bounded IP rate buckets. Alarms expire pending and accepted sessions and notify peers; clients must independently enforce `expiresAt` and stop WebRTC because signaling cannot terminate an established direct connection. Credentials already issued remain usable until their TTL expires. The target must enforce consent, permissions, visible indicators and termination locally. No unattended access or password authentication is implemented.

This is a foundation, not a production security boundary. Per-IP connection limiting uses 256 fixed hashed buckets; collisions share limits, and distributed attackers or multiple connections can still enumerate IDs. The singleton imposes capacity and availability limits. There is no account recovery, identity revocation, audit log, TURN traffic metering, or production abuse protection. Do not expose publicly without security review, stronger distributed abuse prevention, lifecycle testing against Cloudflare and deployment-specific quotas. See [Cloudflare WebSocket guidance](https://developers.cloudflare.com/durable-objects/best-practices/websockets/).

# TV bridge

Pure Dart IO, no package dependencies. Only private IPv4 literals are accepted. The owner approval callback must represent a local user decision, not remote input. Samsung and LG require a previously locally confirmed SHA-256 certificate pin; the digest callback must calculate SHA-256 over DER using trusted native code. Credentials callbacks must use secure storage. Never store pins or credentials from a remote controller without local confirmation. No unencrypted fallback exists for Samsung/LG. Roku ECP itself is unauthenticated plaintext; only use on a trusted LAN.

Capabilities describe protocol implementation, not authorization or guaranteed firmware support. Samsung reports only successful WebSocket transmission, not command execution. LG supports volume up/down, power off, and D-pad through a pinned same-host WSS pointer socket. Screen viewing is not implemented. LG requires an application-supplied registration manifest. Other vendors must use `UnsupportedTvAdapter` with an explicit reason.

`AndroidTvAdapter` (Remote v2, ports 6467 pairing / 6466 remote) pairs with the 6-hex-digit PIN on the TV (secret = SHA-256 of client+server RSA modulus/exponent + PIN bytes) and sends keys and deep-link launches. Pure Dart cannot create RSA certs, so the caller supplies a PEM client cert and key (`openssl req -x509 -newkey rsa:2048 -nodes -keyout k.pem -out c.pem -subj /CN=atvremote`); `TvService` shells out to `openssl` once on desktop and stores both in secure storage. The TV certificate is pinned like Samsung/LG. Text input is not implemented. Fire TV does not advertise Remote v2: it is Tier B (ADB), out of scope here. `VizioAdapter` (SmartCast HTTPS 7345, or 9000 on old models) pairs with a 4-digit PIN, stores the AUTH token as the credential and sends key commands; key codes follow pyvizio and are untested on hardware. SSDP finds Vizio only if its DIAL response carries "vizio" in the headers. `AppleTvAdapter` is an explicit unsupported entry: Apple TV needs HAP pairing (SRP, ChaCha20-Poly1305) and the Companion protocol, infeasible without crypto dependencies. Run `dart test/androidtv.dart` and `dart test/vizio.dart` (need openssl and a private interface; fake TVs bind 6466/6467/7345). Roku's current [ECP documentation](https://developer.roku.com/dev/docs/external-control-api) states third-party platforms may not send ECP commands; assess vendor policy before distribution. No physical device testing has been performed.

Sources: [webOS registration upstream](https://github.com/ConnectSDK/Connect-SDK-Android-Core/blob/master/src/com/connectsdk/service/webos/WebOSTVServiceSocketClient.java), [Roku ECP](https://developer.roku.com/dev/docs/external-control-api).

Run `dart test/smoke.dart` without package:test. The fake HTTP portion binds a private interface port 8060 and never contacts a TV.


`discoverRoku()` performs a two-second, 64-packet-bounded SSDP search and returns unverified private IPv4 source addresses; it never fetches advertised LOCATION URLs. Owner approval is still required. Call `close()` when finished; it terminates in-flight transport and permanently closes the adapter. LG pointer keys are `up`, `down`, `left`, `right`, `enter`, `back`, `home`. Pointer sends are unacknowledged. `dart test/wss.dart` generates a disposable self-signed certificate using Git for Windows OpenSSL and exercises fake servers on ports 8002 and 3001; it never contacts a TV.
